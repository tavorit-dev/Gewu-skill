# 交付前自检清单

## 内容层面（最重要，先过这关）

- [ ] 这张图**只讲一件事**，读完能说出一个明确结论
- [ ] `question` 明确：读者能知道这张图试图解释什么
- [ ] `core_message` 是**判断**，不是同义反复（「Redis 用渐进式 rehash」不算判断）
- [ ] 每条关键关系都有 `evidence` 指向原文依据
- [ ] `unknowns` 写了——如果一项都没有，很可能把不知道的当成了知道的
- [ ] **没有把「可能发生」画成「必然发生」**（用 `style: weak` 区分）
- [ ] 版本相关的技术，`scope.version` 和 `boundary` 都写清楚了
- [ ] 图注独立可读，写的是「读者获得什么判断」，不是「这是 XX 流程图」
- [ ] 图里的数字标明了性质（示意值 / 实测值）

## 视觉层面

- [ ] 核心机制足够突出（用了 `role: primary`，不是所有节点一样重）
- [ ] 颜色语义自洽：同一 role 在同一张图里是同一个颜色
- [ ] 用颜色表达状态差异时**有图例**
- [ ] 实线/虚线表达的是「确定/弱」，不是「主流程/回环」
- [ ] 没有无意义的装饰、渐变、发光
- [ ] 分区边界有语义（不只是把节点框起来）
- [ ] 节点数 ≤ 9，超过就考虑拆图

## 校验（必跑，不要相信「看起来没问题」）

```bash
# 1. 结构与几何：XML 合法性、越界、文字溢出、节点重叠
python3 scripts/render.py diagram.yaml -o diagram.svg --check

# 2. 渲染后像素：尺寸、墨色分布、留白、文字是否渲染出来
python3 scripts/render.py diagram.yaml -o diagram.svg --png diagram.png
python3 scripts/vis_check.py diagram.png --expect "ESTABLISHED" "TIME_WAIT"
```

- [ ] `--check` 无 error（退出码 0）
- [ ] 渲染后墨色占比在合理区间，没有大片死白
- [ ] 内容包围盒四周留白均衡（没有内容贴边）
- [ ] 英文标签 OCR 命中（中文无法用 OCR 断言）

## 落盘层面（宿主是 Hexo 时）

- [ ] 图片在文章**同名目录**里，不是散在 `source/` 下
- [ ] 正文引用是**裸文件名**，无目录前缀
- [ ] `hexo clean && hexo generate` 已执行
- [ ] `find public -type f -empty` 输出为空
- [ ] `find public -type f | wc -l` 数量合理（正常约 97 个）
- [ ] `grep -o '<img[^>]*>'` 能看到实际数量的 `<img>`，不是字面量 `![](…)`
- [ ] VEM 已落盘（`models/*.yaml`），便于后续重渲染
- [ ] 外部素材已在 `## 引用与致谢` 中逐项注明来源、作者、许可

## 能力边界（本环境必读）

**本环境 `Read` 打开图片只返回 `[Image #N]` 占位符，拿不到像素；`analyzeImage` 工具不存在。**
降采样（`sips -Z 800`）解决的是上下文撑爆，**不是**「读不到图」。

| 能验（程序化） | 验不了（必须人眼） |
|---|---|
| XML 合法性、元素白名单、越界 | 文字是否糊 |
| 文字是否超出节点框（测量复算） | 是否有视觉重叠 |
| 节点是否重叠 | **中文是否正确渲染**（缺字显示豆腐块） |
| 尺寸、墨色占比、留白分布 | 排版观感 |
| 英文标签是否渲染出来（OCR） | **技术语义是否正确** |
| GIF 是否真的在动（抽帧比对） | |

本机 `tesseract` 只装了 `eng` 语言包，**中文必然识别成乱码**，
所以 OCR 只能确认「文字渲染出来了」，不能判断中文正确性。

**交付时必须说明哪部分已验、哪部分没验，把视觉终检交给用户。**

**不要把 `--check` 通过说成「图没问题」。** 它只证明图在几何上站得住，
没证明图讲对了机制——机制正确性只能回到 VEM 和原文依据去核。

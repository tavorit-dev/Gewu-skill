# 视觉设计系统

技术感不来自复杂效果，来自**结构清晰、关系准确、布局严谨**。

这份文档是配色、字号、间距的唯一事实源。渲染器从 `scripts/gewu/tokens.py` 读同一套值——
改设计系统改那里，不要在模板里写死色值。

## 配色：语义驱动，不是随机分配

| 视觉角色 | 色值 | 用在哪 |
|---|---|---|
| 背景 | `#ffffff` | 画布 |
| 分区底色 | `#f6f7f9` | 分区背景板 |
| 主文字 / 描边 | `#1f2328` | 所有文字、主描边 |
| 次级文字 | `#6b7280` | 注释、连线标签、虚线 |
| 常规连线 | `#c9ced6` | 普通关系 |
| 常规组件 | `#eef0f3` | neutral 节点填充 |
| **主要执行路径** | `#3b6fd4` | primary |
| **关键状态 / 目标** | `#2f9e8f` | accent |
| **风险 / 阻塞 / 代价** | `#d98324` | warn（克制使用） |
| 异常 / 错误 | `#c8483c` | danger |
| 第四分类色 | `#7c5cbf` | violet（对比图第三、四项） |

### 两条硬规则

1. **同一张图里，同一个 role 永远是同一个颜色。** 红色不能在一处表示「重要」、
   另一处表示「错误」——那样读者无法从颜色推断语义。
2. **用颜色表达状态差异时必须有图例。** 读者不应该靠猜。

### 颜色不承担区分职责时，不要用颜色

结构图里分区之间的区分靠**空间分组和边界**，不是靠每块不同颜色。
对比图里两个方案用同一个 primary 色也是对的——它们的差异由 `dimensions` 的
高亮行表达，不需要靠颜色对立。

## 字号阶梯（五级视觉层次）

| 层级 | 字号 | 作用 |
|---|---|---|
| 图标题 | 26px / 650 | 一句话说明这张图解释什么 |
| 副标题 | 14px | 版本、范围 |
| 分区标题 | 15px / 600 | 空间分组的名字 |
| 节点标签 | 14px | 主体内容 |
| 节点次级 | 11.5px | 补充说明 |
| 连线标签 | 11.5px | 线上写「做什么 / 传什么」 |
| 结论条 | 13px / 550 | 图下方的核心结论 |
| 图例 / 边界 | 11.5px | 版本、假设、示意值声明 |

**11px 是下限。** 低于它渲染器会拒绝缩小并报错——这是刻意的：
PRD 8.3 要求「无法在合理尺寸内清晰表达时应该拆图，而不是不断缩小字体」。

## 间距与几何

| 项 | 值 |
|---|---|
| 画布宽度 | 1100px（高度随内容） |
| 画布外边距 | 32px |
| 同层节点水平间距 | ≥ 56px |
| 层间垂直间距 | ≥ 44px |
| 分区之间 | 22px |
| 分区内边距 | 18px |
| 节点内边距 | 16px（左右）/ 12px（上下） |
| 节点最小 / 最大宽 | 96px / 300px |

### 排版由内容量驱动

**先数清楚要画多少东西，再倒推几何**——不是先定画布再往里塞。

- **横向撑满**：一行节点铺满可用宽度，首尾贴内边距，间隙均分。
  不要把内容挤在中间留两侧大白边。
- **纵向贴内容**：分区高度 = 头部 + 主轴行 + 附件行 + 内边距，逐项加出来。
- **自动换行**：标签超过节点宽度时先折行，折不下才缩字号，缩到 11px 报错。

这些都由渲染器保证，你不需要手算坐标。

## 线型语义

| 线型 | 含义 |
|---|---|
| 实线 | 确定的、必然发生的关系 |
| `weak` 虚线 | 弱关联、可选路径、可能发生 |
| `async` 点线 | 异步、非阻塞 |
| `data` 长虚线 | 数据面、批量 |

**实线/虚线表达的是「确定 / 弱」，不是「主流程 / 回环」。**
如果迭代循环是核心流程，就用实线，不要因为它是「绕回去的」就用虚线弱化。

## 图形语言

优先使用：

- 简洁的几何形状（矩形、圆角矩形、胶囊、菱形）
- 明确的方向箭头
- **有意义的空间分组**——分区边界本身就是信息
- 适度的留白
- 清晰的视觉层级
- 一致的线宽（1.2~2.0px）

避免：

- 无意义的装饰性发光、渐变、阴影
- 过度拟物
- 纯粹为了视觉效果添加的组件
- 大量小字和密集连线
- **与实际技术机制不符的隐喻**（用一个「管道」比喻去画一个非流式的东西）

## 视觉层次：一张图从上到下的阅读顺序

1. **标题** —— 这张图解释什么
2. **核心机制** —— 图形中最重要的部分（用 `role: primary` 标记）
3. **辅助解释** —— 必要的标签、步骤、条件
4. **结论** —— 帮读者快速抓住机制的句子
5. **边界说明** —— 版本、假设、示意值

**不要在图中重复整段文章。** 每个标签尽量简短，详细解释留给图下的配套文案。

## 自检：眯眼看整图

- 墨色分布均匀吗？哪块区域一眼看过去「一片空」？
- 核心机制是不是最突出的？还是所有节点看起来一样重？
- 有没有无意义的装饰？
- 有没有不必要的交叉连线？
- 在实际阅读尺寸下（手机上大约 375px 宽），文字还看得清吗？

最后一条尤其重要：**图会出现在手机屏幕上**。1100px 宽的图缩到 375px 时，
14px 的字只剩约 4.8px。所以图组里的图不要塞太多节点——
宁可多画一张，也不要把一张图塞满。

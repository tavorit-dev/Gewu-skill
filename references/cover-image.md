# 封面图

封面图的作用是**让读者决定要不要点进来**，不是装饰文章。所以它要传达文章的主题或气质，而不是随便一张好看的科技感图片。

## 选图原则

**按元信息筛选，不要靠读图。** 优先用文件名、尺寸、来源页的标题和标签判断是否贴合主题，把真正需要视觉确认的留给最终入选的那一张。读图成本极高（见 SKILL.md「读图之前先降采样」）。

尺寸要求：

```bash
sips -g pixelWidth -g pixelHeight cover.jpg
```

- 长边 **1200px 以上**（NexT 主题的封面区域会做裁切，太小会糊）
- 比例不敏感，主题会裁成固定宽高比，**主体别贴边**——裁切会切掉边缘

## 来源

**默认自托管**：把图片放进文章同名资源目录，随文章一起提交。这样图片不依赖第三方可用性，也不会因为外链图床挂了而 404。

如果确实要从图库（Unsplash 等）取图：

1. 下载到文章同名目录，**不要热链**
2. 在文末 `## 引用与致谢` 里写明来源、作者、许可（Unsplash 图片是 Unsplash License，需署名）
3. 确认许可允许再分发——**不确定就不要用**

**注意**：本 skill 不包含「从 Unsplash 自动获取图片」这一步。图库 API 的可用性、许可条款和配额都会变，把这一步固化进 skill 只会让它悄悄坏掉。选图是人的判断，不是流程步骤。

## 引用

放在文章同名目录里，正文用**裸文件名**引用：

```markdown
![](cover.jpg)
```

NexT 主题若开启了 `cover` 相关配置，封面也可以走 front-matter：

```yaml
---
title: 文章标题
date: 2026-10-23 10:00:00
tags: Redis,数据结构
---
```

具体字段名以宿主主题版本的文档为准——NexT 8 与老版差异较大，别照抄旧教程。

## 校验

生成后确认封面真的被解析了（不要只看源文件）：

```bash
grep -o '<img[^>]*>' "public/2026/10/23/<文章名>/index.html"
```

看到 `<img>` 且 `src` 指向该文章目录的百分号编码路径才算成功。看到字面量 `![](…)` 就是路径写法错了。
